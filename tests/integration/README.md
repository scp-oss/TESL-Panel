# Сквозной интеграционный тест: TESL-Manager → TESL-Panel → TESL

Три отдельных git-репозитория (`scp-oss/TESL-Manager`, `scp-oss/TESL-Panel`,
`scp-oss/TESL`), которые физически не могут существовать по отдельности —
у них один общий протокол (`depot_manifest.json`/`chunk_index.db`/
`extras_manifest.json`/отчёты), но до этого он проверялся только руками,
по одному разу на каждую правку. Два реальных бага 2026-09-29 (коллизия
имён pack-файлов при повторной публикации, случайно ставшая публичной
только половина эндпоинтов отчётов) прошли бы этот тест сразу, если бы
он существовал раньше — оба нашлись только на реальной установке у
пользователя.

## Когда гонять

Перед тем как считать готовой любую правку, которая касается протокола
между репозиториями — формата `depot_manifest.json`/`chunk_index.db`/
`extras_manifest.json`, эндпоинтов `/api/...`, публикации через
`execute_sync_packed()`, чтения через `PanelDepotClient`/`ChunkInstaller`.
Не нужен для правок, ограниченных одним репозиторием и не трогающих
протокол (например, UI-правка в `/admin`, не меняющая формат ответа).

## Требования

Соседние чекауты **рядом** с этим репозиторием (одна директория выше):

```
parent/
  TESL-Panel/     (или tesl-panel — этот репозиторий)
  TESL-Manager/   (или tesl-manager)
  TESL/           (или tesl)
```

Без соседей тест сам себя пропускает (`pytest.skip`, не красный) с
понятным сообщением — это разработческий тест, не CI-гейт, который
обязан гонять кто угодно, клонировавший один из трёх репозиториев в
одиночку.

```bash
pip install pytest
cd TESL-Panel
pytest tests/integration/ -v -s
```

`-s` стоит держать — сами подпроцессы (`manager_publish.py`/
`launcher_verify.py`) печатают происходящее, полезно при диагностике
падения.

## Что реально проверяется

1. **Два раунда публикации на один build_id** (не один — предыдущий тест
   этого репозитория ловил только single-shot публикацию, поэтому не
   поймал баг коллизии имён pack-файлов при ПОВТОРНОЙ публикации).
   Раунд 1 публикует `Skyrim/Data/{Skyrim.esm,Update.esm}` +
   `MO2p/ModOrganizer.exe`; раунд 2 добавляет новые файлы, НЕ трогая
   файлы раунда 1. Крошечный `pack_size` (96KB) форсирует несколько
   pack-файлов, чтобы коллизия имён между раундами была реально
   достижима на скромном объёме синтетических данных.
2. **TESL-лаунчер реальным клиентским кодом** (`PanelDepotClient` +
   `ChunkInstaller`, тот же путь, что `core/workers.py::DownloadWorker`)
   скачивает и устанавливает — байт-в-байт сверка каждого файла с
   оригиналом, включая специально нетронутый файл раунда 1 (та самая
   лакмусовая бумажка на регрессию коллизии pack-файлов).
   `client.chunk_error_summary()` должен быть пуст — любой
   `sha256_mismatch`/`http_416`/`timeout` здесь — это ровно тот баг,
   который тест написан ловить.
3. Документы/патчи/файлы патчей/постер — публикуются и читаются обратно
   через `extras_manifest.json`/`fetch_poster()`.
4. Отчёты (`crash`/`debug_log`) — публичная отправка (без токена, см.
   TESL-Panel/CLAUDE.md) реальным `core.crash_logger.upload_files()`,
   видимость через `reports_storage`; `manager_log` — отдельно
   проверено, что ОСТАЁТСЯ за токеном (не должен был случайно стать
   публичным вслед за `crash`/`debug_log`).

## Почему подпроцессы, а не прямой импорт

`manager_publish.py`/`launcher_verify.py` запускаются `subprocess.run()`,
не импортируются в процесс pytest напрямую — у TESL-Manager
(`depot_sync_manager/panel_client.py`, `depot_sync_manager/config.py`) и
у TESL (`launcher/core/panel_client.py`, `launcher/config.py`) есть
модули с ОДИНАКОВЫМИ именами. `import panel_client`/`import config` в
одном процессе после того, как оба каталога уже добавлены в `sys.path`,
вернёт уже закэшированный чужой модуль через `sys.modules` — рабочий
обходной путь через `importlib.util.spec_from_file_location` есть, но
сами эти модули ВНУТРИ себя делают `import config` (не абсолютный путь) —
подгрузка одного под другим именем не спасает от коллизии их собственных
внутренних импортов. Два независимых процесса с непересекающимся
`sys.path` — надёжнее.

## Что тест НЕ проверяет

- Реальную сеть/Cloudflare/скорость — только localhost, `127.0.0.1`.
- GUI TESL-Manager (`main_window.py`/`depot_tab.py` и т.п.) — только
  сам движок публикации (`DepotSyncManager`/`ChunkManager`), без Qt-виджетов.
- GUI лаунчера (`ui/main_window.py`) — только клиентские модули
  (`core/panel_client.py`/`core/chunk_installer.py`/`core/workers.py`'s
  свободные функции), без QThread/сигналов вокруг них.
